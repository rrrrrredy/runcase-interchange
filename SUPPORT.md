# Support

Use GitHub Issues for reproducible CLI or schema bugs and narrowly scoped protocol proposals. A useful report names the package version, schema identifier, Node version, exact exit code, and the smallest synthetic document that reproduces the behavior.

Before filing a proposal, explain which producer and consumer need the change, whether the field is portable across products, and why the `extensions` object is insufficient. Product-specific database, UI, runner, or environment behavior does not belong in this protocol.

Never attach credentials, proprietary Runs, private task data, or resolvable local content-store objects. Reduce the report to synthetic data first. Security-sensitive reports follow [SECURITY.md](SECURITY.md), not a public issue.

The 0.1 prerelease has no commercial support or response-time SLA.
